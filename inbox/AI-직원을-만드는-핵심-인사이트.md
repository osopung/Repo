# AI 직원을 만드는 핵심 인사이트

## 1. AI를 ‘질문에 답하는 도구’에서 ‘정해진 일을 하는 직원’으로 바꾼다

AI에게 매번 이메일 정리나 일정 확인을 요청하는 대신, 다음 요소를 미리 설정한다.

```text
직원 정체성
→ 기억
→ 업무 규칙
→ 업무 매뉴얼
→ 실행 일정
→ 보고 채널
```

그러면 AI가 정해진 시간에 업무를 수행하고 결과를 보고하는 구조가 된다.

> **AI 직원은 좋은 프롬프트 하나가 아니라, 반복 업무를 맡길 수 있는 운영 체계다.**

## 2. AI 직원 세팅의 다섯 가지

### ① `SOUL.md`: 직원의 정체성

AI가 어떤 직원인지 정한다.

- 이름과 역할
- 담당 업무
- 미션
- 말투와 태도
- 중요하게 여길 기준
- 하지 말아야 할 일
- 보고 방식

`SOUL.md`는 직원의 신분증이자 직무기술서다. 처음부터 완벽하게 쓰기보다 AI에게 초안을 만들게 한 뒤, 실제로 사용하면서 고쳐 가는 것이 좋다.

### ② `USER.md`와 `MEMORY.md`: 사용자와의 기억

사용자의 정보와 반복되는 선호를 저장한다.

- 사용자의 호칭
- 답변 형식과 말투
- 장기적인 취향
- 업무 원칙
- 반복해서 적용할 규칙

기억에는 한계가 있으므로 모든 것을 넣으면 안 된다.

> **오래 유지될 중요한 정보만 남기고, 일회성 작업과 임시 계획은 저장하지 않는다.**

기억을 새로 추가한 뒤 바로 반영하려면 새 세션을 시작해 다시 로드해야 할 수 있다.

### ③ `AGENTS.md`: 공통 업무 규칙

AI가 조직이나 프로젝트에서 일할 때 지켜야 할 공통 규칙을 둔다.

- 보안 원칙
- 작업 경로
- 파일 저장 위치
- 커뮤니케이션 방식
- 보고 양식
- 판단이 필요한 상황
- 공통 작업 절차

`SOUL.md`가 “어떤 직원인가”를 설명한다면, `AGENTS.md`는 “어떻게 일해야 하는가”를 설명한다.

### ④ Skills: 구체적인 업무 매뉴얼

특정 업무를 수행하는 세부 절차는 스킬로 분리한다.

예:

- 모닝 브리프 작성
- 이메일 요약
- 시장 조사
- 보고서 작성
- 이미지 생성
- 파일 백업

`AGENTS.md`에 모든 절차를 길게 넣으면 문서가 비대해진다. 공통 규칙은 `AGENTS.md`에 두고, 반복 업무의 자세한 순서는 스킬로 나누는 것이 좋다.

### ⑤ Cron과 보고 채널: 출근 시간과 보고 장소

AI가 언제 어떤 일을 할지 정한다.

- 매일 오전 10시 모닝 브리프
- 매월 1일 메모리 점검
- 평일 특정 시간 시장 뉴스 확인
- 매주 업무 결과 종합

그리고 결과를 Telegram, Slack, 이메일, 로컬 파일 등 필요한 곳으로 보낸다.

> **업무 일정과 보고 채널이 연결되어야 AI가 실제 직원처럼 작동한다.**

## 3. 기억과 업무 매뉴얼을 한곳에 넣지 않는다

각 문서의 역할을 분리해야 한다.

| 문서 | 역할 |
|---|---|
| `SOUL.md` | 직원의 정체성·태도·미션 |
| `USER.md` | 사용자의 기본 정보와 선호 |
| `MEMORY.md` | 장기적으로 기억할 사실 |
| `AGENTS.md` | 공통 업무 규칙과 작업 방식 |
| Skills | 특정 업무의 상세 매뉴얼 |
| Cron | 실행 시간과 반복 일정 |

> **정체성, 기억, 규칙, 매뉴얼, 일정은 서로 다른 층위다.**

## 4. 문서는 짧게 시작하고 사용하면서 발전시킨다

처음부터 거대한 업무 매뉴얼을 만들 필요는 없다.

1. `SOUL.md`와 기본 기억을 설정한다.
2. 간단한 업무 하나를 시킨다.
3. 결과를 확인한다.
4. 부족한 점을 규칙이나 스킬에 추가한다.
5. 원하는 결과가 안정되면 Cron으로 자동화한다.
6. 이후 업무를 조금씩 확장한다.

> **AI 직원은 한 번에 완성하는 것이 아니라, 실제 업무를 시키며 온보딩한다.**

## 5. 메모리는 정기적으로 검진한다

`USER.md`와 `MEMORY.md`는 용량 제한이 있으므로 주기적으로 점검해야 한다.

점검할 내용:

- 더 이상 필요 없는 기억
- 현재 선호와 달라진 과거 정보
- 중복된 내용
- 압축할 수 있는 긴 문장
- 반드시 유지해야 할 핵심 원칙

AI에게 먼저 정리 후보와 유지해야 할 핵심을 표로 제안하게 한 뒤, 사람이 선택해 정리하는 방식이 안전하다.

## 6. 큰 업무는 계획하고, 작은 업무는 바로 시킨다

업무가 복잡할수록 한 번에 실행하지 말고 먼저 계획을 세운다.

```text
목표 확인
→ 필요한 자료 확인
→ 업무 순서 작성
→ 계획 승인
→ 실행
→ 결과 보고
```

> **작은 일은 자동 실행하고, 큰 일은 계획과 승인을 거친다.**

## 7. 자동화에는 안전장치가 필요하다

반복 작업을 예약할 때는 결과를 항상 보고할지, 조건이 있을 때만 알릴지, 파일만 저장할지 구분해야 한다.

- 보고가 필요한 작업은 Telegram이나 Slack으로 전달
- 단순 산출물은 로컬 파일로만 저장
- 변화가 있을 때만 알림
- 단순 조건 확인은 스크립트 기반 watchdog으로 실행
- 앞선 작업의 결과를 다음 작업에 넘길 때는 실행 시점을 정확히 설계

이메일 전송, 외부 공개, 삭제, 결제 같은 작업은 자동 실행보다 승인 절차를 두는 것이 안전하다.

## 8. AI 직원이 많아지면 프로필로 역할을 나눈다

한 명의 AI에게 모든 일을 맡기기보다 필요할 때 역할별로 나눌 수 있다.

- 콘텐츠 담당
- 리서치 담당
- 영업 담당
- 일정 담당
- 재무 담당

각 프로필마다 정체성, 기억, 업무 규칙, 스킬, 보고 채널을 다르게 설정할 수 있다. 다만 처음부터 여러 직원을 만들기보다, 한 명을 먼저 제대로 운영한 뒤 확장하는 것이 좋다.

## 오소풍님에게 적용할 핵심

오소풍님의 현재 Hermes 운영 구조는 이미 이 방향과 상당 부분 맞다.

- Hermes: 24시간 그림자 개인비서
- 메모리: 장기적으로 유지할 사용자 원칙
- Skills: 반복 업무 절차
- GitHub 위키: 선별한 기록 보관
- Telegram: 보고 채널
- Cron: 정해진 시간의 반복 업무

앞으로 필요한 것은 기능을 많이 추가하는 것이 아니라:

1. 업무별 매뉴얼을 스킬로 분리하고
2. 반복 업무만 Cron으로 자동화하고
3. 보고가 필요한 일과 조용히 처리할 일을 구분하는 것이다.

## 한 줄 정리

> **AI 직원을 만드는 일은 정체성·기억·규칙·매뉴얼·일정·보고 체계를 갖춘 업무 시스템을 설계하는 일이다.**
