# 프롬프트

## 핵심 인사이트

### 1. 프롬프트는 질문이 아니라 업무 설계서다

좋은 프롬프트는 AI에게 단순히 정보를 묻는 문장이 아니다. AI가 인간의 의도를 정확히 이해하고 비즈니스 목적에 맞는 결과물을 만들도록 설계하는 **작업지시서**다.

프롬프트에는 최소한 다음 요소가 들어가야 한다.

```text
목적 + 대상 + 행동 + 형식 + 제약조건
```

오소풍님이 사용하는 다음 지시 구조와도 일치한다.

```text
목적 + 자료 + 형식 + 금지사항 + 실행 여부
```

### 2. 명확한 행동과 결과물 형식을 먼저 정한다

“설명해줘”처럼 모호한 표현은 AI의 추측을 키운다. 대신 무엇을 어떻게 만들지 명시해야 한다.

- 요약해
- 비교표로 작성해
- 5단계로 정리해
- 장단점을 나눠 제시해
- 실행 순서로 구성해

핵심은 다음이다.

> **명확한 행동 동사 + 구체적인 결과물 형식**

### 3. 맥락은 한 번에 패키징한다

AI가 상황을 오판하지 않도록 다음 정보를 함께 전달한다.

- **목적:** 궁극적으로 무엇을 달성하려는가
- **대상:** 누가 결과물을 읽거나 사용하는가
- **톤:** 전문적·친절함·격식 등 어떤 어조인가
- **길이·형식:** 분량, 불릿 수, 표·마크다운 사용 여부
- **제약조건:** 반드시 포함하거나 금지할 내용

맥락을 나누어 여러 번 보충하는 것보다 처음부터 패키지로 제공하는 편이 안정적이다.

### 4. 정보가 부족하면 핵심 질문 하나만 하게 한다

AI가 모호한 요청에 질문을 너무 많이 던지면 작업이 지연된다. 다음 지침이 실용적이다.

> 정보가 부족하면 가장 중요한 질문 1개만 먼저 하고, 나머지는 합리적으로 가정해 진행하라.

이 원칙은 AI가 지나치게 소극적이거나 제멋대로 추측하는 문제를 함께 줄인다.

### 5. 모델마다 역할을 나눠 사용한다

문서가 제시하는 모델별 경향은 다음과 같다.

- **Claude:** 긴 문맥과 세밀한 규칙·제약조건 준수
- **Gemini:** 이미지·차트 분석과 문서·시트 등 워크스페이스 연동
- **추론 모델:** 복잡한 비교와 논리적 검토

다만 이는 절대적인 법칙이 아니라 모델을 선택할 때 참고하는 실무적 경향으로 봐야 한다. 모델의 실제 성능은 버전과 과업에 따라 달라질 수 있다.

### 6. AI에게 프롬프트 설계 자체를 맡긴다

AI를 단순한 실행자가 아니라 **질문 설계 파트너**로 활용할 수 있다.

```text
이 목적을 가장 잘 달성할 수 있도록
목적·대상·형식·제약조건이 포함된 프롬프트를 설계해줘.
내 의도는 최소한으로 수정해.
```

실제 흐름은 다음과 같다.

```text
내 목적 설명 → AI가 프롬프트 설계 → 사람이 의도 확인 → 실제 실행
```

### 7. AI의 아첨을 막는 검증 장치를 넣는다

AI가 사용자의 의견에 맹목적으로 동의하면 확인편향과 잘못된 의사결정이 생길 수 있다. 따라서 다음을 명시한다.

- 내 전제가 틀리면 분명히 지적하라.
- 사실과 의견을 구분하라.
- 찬성과 반대 근거를 모두 제시하라.
- 불확실한 부분은 불확실하다고 표시하라.
- 확신 수준을 밝혀라.
- 제3자의 관점에서 반론을 제시하라.

핵심은 **동의하는 비서가 아니라 검토하는 비서**를 만드는 것이다.

### 8. 출처 검증은 표준 절차다

최신 정보나 중요한 판단을 다룰 때는 출처 표시를 요구해야 한다.

```text
본문 각 단락 끝에
(기관·연도·링크) 형식으로 출처를 표시해.
```

다만 출처 형식을 요구하는 것만으로 진실성이 보장되지는 않는다. AI가 제시한 출처의 실제 존재 여부와 해당 내용이 원문에 있는지를 별도로 확인해야 한다.

## 오소풍님의 작업에 적용

### Hermes·Codex 협업

- **Hermes:** 자료 검색, 목적 정리, 프롬프트 설계, 결과 검토
- **Codex:** 코드 구현, 테스트, 오류 수정
- **오소풍님:** 목적 결정, 우선순위 판단, 최종 승인

### 자료 큐레이션

```text
목적: 오늘 실제로 적용할 자료를 찾는다.
대상: AI 초중급 학습자인 오소풍님
형식: AI 4개·다큐 3개·캘리그래피 3개
제약: 최근 1년, 중복 금지, 한글 우선, 영문은 번역 첨부
검증: 게시일·출처·확인 상태 표시
```

### 작품·글쓰기

```text
목적: 대화에서 작품의 씨앗을 추출한다.
자료: 녹취 원문
형식: 핵심 내용·기억할 문장·작품의 씨앗·삶의 원칙
제약: 원문을 과도하게 미화하지 말 것, 불확실한 내용은 표시할 것
실행: 초안을 먼저 보여주고 승인 후 위키에 기록
```

## 표준 워크플로우

```text
1. 목적과 결과물 정의
2. 맥락 패키징
3. 과업에 맞는 모델 선택
4. 필요한 경우 프롬프트 설계부터 AI에게 요청
5. 출처·반론·불확실성 검증
6. 사람이 최종 승인
```

## 주의할 점

- 모델별 특성은 참고 경향이지 보장된 법칙이 아니다.
- “Think Hard” 같은 지시어만으로 답변의 정확성이 보장되지는 않는다.
- 금융·의료·법률 정보는 별도 출처 검증이 필요하다.
- AI가 표시한 확신도와 실제 정확도가 일치한다고 볼 수 없다.
- AI가 만든 출처는 반드시 실제 원문과 대조해야 한다.
