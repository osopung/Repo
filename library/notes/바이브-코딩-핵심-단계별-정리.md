# 바이브 코딩 핵심 단계별 정리

## 내 한 줄

**바이브 코딩은 코드를 AI에게 맡기는 일이 아니라, 사람이 목적·구조·예외·우선순위를 정하고 AI를 구현자로 지휘하는 방식이다.**

- [x] 감수


## 핵심 사례: 18분 만에 끝난 번역과 편집

프롬프트 창에 자연어로 한 문장을 입력했을 뿐인데, AI 에이전트가 약 18분 만에 두꺼운 책의 번역과 편집을 끝냈다는 사례가 소개된다.

이 작업은 단순히 문장을 기계적으로 바꾼 것이 아니었다. AI는 책 전체의 맥락을 파악하고, 내용을 12개 장으로 나누고, 여러 작업창에서 동시에 번역하며, 용어집을 공유해 문맥의 일관성을 유지했다.

> **핵심: AI는 단순한 번역기가 아니라, 작업을 나누고 배분하는 프로젝트 관리자로 움직일 수 있다.**

---

## 1단계: 사람이 직접 실행한다

- 사람이 텍스트를 한 줄씩 번역하고 수정한다.
- 코딩도 사람이 문법과 명령어를 직접 작성한다.
- 반복 작업과 시간 부담이 크다.

> 비유: 손빨래

## 2단계: 코드를 짜서 반복 작업을 자동화한다

- 프로그램이 복사·붙여넣기와 파일 처리를 대신한다.
- 정해진 순서에 따라 작업을 자동으로 진행한다.
- 코딩 지식, API 인증 키, 환경 설정이 필요하다.

> 비유: 컨베이어 벨트

API는 서로 다른 프로그램을 연결하는 통로이고, 인증 키는 그 통로를 사용할 권한을 증명하는 열쇠와 같다.

## 3단계: AI 에이전트에게 목표를 맡긴다

- 사람은 “이 책을 번역해 줘”처럼 최종 목표를 자연어로 설명한다.
- AI가 작업을 나누고, 순서를 정하고, 여러 작업을 동시에 수행한다.
- 사람은 세부 실행보다 목적과 결과의 품질에 집중한다.

> **핵심 변화: 인간은 단순 실행자에서 시스템 전체의 방향을 정하는 의사결정자·지휘관으로 이동한다.**

---

# 바이브 코딩이란?

바이브 코딩은 코딩 문법을 직접 작성하기보다, 자연어로 원하는 결과와 느낌을 설명하면서 AI와 함께 프로그램을 만들어 가는 방식이다.

1. AI에게 원하는 결과를 설명한다.
2. AI가 코드를 만들고 결과물을 보여 준다.
3. 결과를 직접 확인한다.
4. 부족한 점과 원하는 느낌을 말한다.
5. 만족할 때까지 반복해서 개선한다.

처음부터 완벽한 설계도를 만드는 방식이 아니라, 스케치를 함께 보며 다듬어 가는 방식이다.

> **바이브 코딩은 코드를 AI에게 무조건 맡기는 일이 아니다. 사람이 목적·구조·품질 기준을 정하고 AI를 구현자로 지휘하는 일이다.**

# 바이브 코딩의 세 가지 핵심 원리

## ==1. 모듈화

큰 작업을 작은 단위로 나눈다.

소설이라면 다음을 따로 관리할 수 있다.

- 인물 설정
- 사건
- 장면
- 시간 순서
- 문체

중앙 설정 파일에서 주인공의 나이를 18세에서 19세로 바꾸면, 연결된 전체 원고에 같은 설정을 적용할 수 있다.

> **큰 결과물을 레고 블록처럼 나누면 수정·재사용·확장이 쉬워진다.**

## ==2. 버전 관리

원본을 보존한 채 복사본에서 새로운 시도를 한다.

- 원본은 안전하게 보관한다.
- 실험용 버전에서 새로운 결말이나 기능을 시험한다.
- 결과가 좋으면 반영한다.
- 실패하면 원본으로 돌아간다.

버전 관리는 실패의 비용을 낮추고, 과감한 실험을 가능하게 한다.

## ==3. 자동화와 테스트

AI에게 사람이 지치기 쉬운 반복 검사와 오류 확인을 맡긴다.

- 인물 설정의 일관성 검사
- 용어가 다르게 쓰인 부분 찾기
- 여러 채널의 문구 동시 수정
- 문서의 누락과 오류 검사
- 데이터의 이상한 변화 찾기

AI는 기계적인 검사를 빠르게 수행하고, 사람은 창의적인 판단에 집중한다.

# 중요한 한계: ==프로토타입과 실제 서비스는 다르다

AI는 짧은 시간에 그럴듯한 프로그램을 만들 수 있다. 그러나 내 컴퓨터에서 잘 작동하는 것과 다른 사람이 안정적으로 사용하는 것은 다르다.

실제 환경에서는 다음 문제가 생길 수 있다.

- 인터넷 연결이 끊긴다.
- 사용자가 버튼을 여러 번 누른다.
- 데이터가 비어 있거나 잘못 입력된다.
- 로그인·인증이 만료된다.
- 휴대전화 화면에서 글자가 깨진다.
- 여러 사용자가 동시에 접속한다.
- 배포 환경과 개발 환경이 다르다.
- 환경 변수·도메인·빌드 설정이 맞지 않는다.

> **전체 노력의 대부분은 첫 번째 프로토타입 이후에 들어간다. 배포, 오류 처리, 보안, 사용성 검증을 결코 가볍게 보면 안 된다.**

## AI가 버그를 만든 것만이 문제는 아니다

AI는 요청받은 기능을 기계적으로 구현한다. 문제는 사람이 요청하지 않은 예외 상황에서 발생하는 경우가 많다.

나쁜 지시:

> 할 일 추가 버튼을 만들어 줘.

좋은 지시:

> 할 일 추가 버튼을 만들어 줘. 사용자가 한 번 누르면 처리될 때까지 버튼을 비활성화해 줘. 인터넷이 끊기면 입력 내용을 임시 저장하고 연결되면 다시 전송해 줘. 같은 항목이 중복 저장되지 않게 해 줘.

> **결과물의 수준은 AI의 속도만이 아니라, 사람이 얼마나 구체적으로 예외 상황을 상상하고 지시하는가에 따라 달라진다.**

# 인간이 집중해서 길러야 할 네 가지 능력

## 1. 시스템 사고

한 기능이 전체 시스템에 어떤 영향을 주는지 바라보는 능력이다.

## 2. 프로덕트 감각

기능을 계속 추가하는 것이 아니라, 사용자에게 필요 없는 기능은 과감히 빼는 판단이다.

## 3. 비즈니스 맥락 이해

만드는 데 드는 비용과 실제로 얻는 효과를 비교하는 능력이다.

## 4. 트레이드오프 판단

완벽한 결과를 기다릴지, 조금 부족해도 먼저 출시할지 결정하는 능력이다.

> **AI는 계속 무언가를 추가하는 데 강하지만, 무엇을 빼야 하는지와 무엇을 포기할지는 인간이 결정해야 한다.**

# 배우는 방법: 위에서 아래로 익힌다

예전에는 문법과 명령어부터 배우는 아래에서 위로의 학습이 일반적이었다.

바이브 코딩 시대에는 다음과 같이 배울 수 있다.

1. 만들고 싶은 프로그램을 먼저 정한다.
2. AI에게 실제 결과물을 만들어 달라고 한다.
3. 작동하지 않는 부분을 직접 경험한다.
4. 오류가 난 이유를 AI에게 묻는다.
5. 필요한 개념을 그때 배운다.
6. 예외 상황을 추가로 지시한다.
7. 테스트하고 다시 개선한다.

오류를 피하기만 하는 것이 아니라, 오류를 통해 API·환경 변수·데이터베이스 같은 핵심 개념을 이해하는 방식이다.

> **문법을 먼저 전부 외우는 대신, 실제 문제를 해결하면서 필요한 개념을 배우고 시스템을 이해한다.**

# 오소풍님의 작업에 적용하기

예를 들어 월배당 ETF 프로그램을 만들 때 다음처럼 지시할 수 있다.

> 국내외 ETF를 모두 원화로 표시해 줘. ETF별 가격, 보유 수량, 평가액, 비중, 평가손익, 예상 배당금을 보여 줘. 공식 발표가 없는 배당금은 추정하지 말고 확인 필요로 표시해 줘. 계산값은 참고용으로 표시해 줘. 화면은 복잡하지 않게 하고, 10개 이하 종목을 한눈에 비교할 수 있게 해 줘.

좋은 지시에는 다음이 들어간다.

- 목적
- 관리할 자료
- 화면에 보여 줄 항목
- 계산과 판단의 기준
- 제외할 기능
- 예외 상황 처리
- 결과 형식
