# 에이전트 4대 개념 ★5

> 검색: **5스타** · **5*** · 에이전트 4대 개념 · 멘탈 모델 · 헌법 · 하네스  
> 출처: 2026-09-04 김효율 「AI 에이전트! 이거 없으면 100% 멍청합니다」 · [[_archive/youtube-에이전트-4대개념-스크립트|스크립트]]

## 내 한 줄

(초안) AI가 멍청한 게 아니라 헌법이 없는 것 — 규칙(글로벌 MD=헌법 · 프로젝트 MD=팀 규칙) · 세션 분리 · 컨텍스트(80% 의도적 압축 · 세 번이면 폐기) · 스킬(규칙은 헌법에, 스킬은 가볍게). 우리 집은 이 그림에 이미 가깝고, 헌법 226줄은 다이어트 후보.

- [ ] 감수

## 형광 — 영상이 칠한 문장

### 0. 진단

- AI를 잘 쓰는 사람들조차 막상 열어 보면 **규칙 설정이 하나도 안 되어 있다.** CLAUDE.md·AGENTS.md가 아예 없는 경우도 많다.
- 「내 AI만 이상한가?」— AI가 이상한 게 아니고 사용자가 잘못한 것도 아니다. **생각하는 AI와 실제 AI가 다를 뿐** (멘탈 모델).
- **AI는 다 해 주는 천재가 아니라, 이제 막 들어온 신입사원.**

### 1. 규칙 — 헌법과 팀 규칙

- 회사 비유: **글로벌 폴더의 CLAUDE.md/AGENTS.md = 회사 헌법** · 프로젝트 폴더의 MD = 팀 규칙 (헌법 안 자율) · 스킬 = 팀 안의 직원(도구).
- 글로벌 폴더: 맥 유저 폴더에서 `Cmd+Shift+.` → `.claude` · `.codex` 가 보인다.
- 카파시도 「규칙 설정이 중요하다」. 초창기 1,000줄짜리 헌법 → **200줄 넘으면 에이전트가 헷갈린다**가 정설에. 김효율 본인은 170여 줄 + 「200줄 넘기지 말라」는 규칙까지 둠.
- **규칙 설정 여부에 따라 답변 방식부터 다르다.**
- 가중치: **가까운 쪽 규칙부터 더 중요하게 읽는다** (프로젝트 MD > 글로벌 MD).

### 2. 세션 — 몰빵 금지

- 신입 디자이너 뽑아 놓고 개발 책 → 재무 공부까지 시키면 짬뽕. **맥락이 사라진다. 사람도 AI도 똑같다.**
- **한 명의 에이전트에게 몰빵은 위험. 세션을 쪼개라.** 김효율의 세션들: 모더레이터(총괄·오른팔) / 슈리(개발) / 애드나(디자인) / 비스트(마케팅).

### 3. 컨텍스트 — 압축과 세션 수명

- **자동 압축(100%)은 어떤 문서가 사라지는지 모른다.** → **80%에서 의도적 압축** (최근 작업 100% 남기고 역순 가중). 김효율은 이걸 `로우프레스` 단축어로 — 옵시디언 저장 + Git 커밋까지 한방에.
- 압축은 **복사본의 복사본** — 반복하면 글씨가 연해지듯 에이전트가 멍청해진다. 그래서 **세 번 압축한 세션은 버리고** 같은 역할의 새 세션을 연다.
- 맥락은 어떻게? **옵시디언에 저장해 두고, 새 세션에서 「옵시디언 참조」로 복원** (세컨드 브레인).
- **서브에이전트** = 눈에 안 보이는 부하직원. 컨텍스트를 아끼며 병렬·분기. **BTW** = 세션 컨텍스트에 절대 안 잡히는 사이드 창 (단, 저장 안 됨 — 좋은 답은 복사해 와야).
- 토큰: **한글은 더 잘게 쪼개진다** (Hello = 1토막, 안녕하세요 = 5토막). 100만 토큰을 실질적으로 다 못 쓴다.
- 기억: **처음과 끝 맥락을 가장 잘 기억, 가운데는 30% 이하로 떨어진다** → **계획 모드로 첫 세션에 해야 할 일을 정확히 박아 둬라.**

### 4. 스킬 — 규칙은 헌법에, 스킬은 가볍게

- 「스킬대로 안 해요」→ **자꾸 까먹으면 스킬이 아니다.** 망치가 오늘은 못 박고 내일은 안 박으면 도구가 아니다.
- 원인 사례: 스킬마다 사용법 규칙을 덕지덕지 — **망치 하나 쓰려고 책 세 권 읽는 셈.** 정작 헌법·팀 규칙은 없었다.
- **스킬 자체가 규칙으로 이루어진 하나의 MD 파일(SKILL.md).** 두 번 시키든 세 번 시키든 똑같이 해내는 것 = 스킬.
- 로봇 비유: 밥 짓기·빨래·청소 = **스킬**(기능) · 「밥 되는 동안 빨래, 빨래 되는 동안 청소」 = **워크플로우**(순서) · 「쌀은 네 컵만 · 흰옷 색옷 분리 · 마른 청소 먼저」 = **하네스**(통제 규칙). 같은 워크플로우도 하네스가 달라지면 일하는 방식이 달라진다.

### 5. 메모리 — 헤르메스 3종과 도서관

- 헤르메스: **SOUL.md(헌법) · MEMORY.md(업무 기억) · USER.md(일 시키는 사람의 성향·이슈)** — 세 가지를 다 기억해서 에이전트로서 효율이 높다고 추천.
- 클로드·코덱스는 USER.md가 없고, SOUL ≒ CLAUDE.md/AGENTS.md, MEMORY는 프로젝트별.
- **옵시디언 맥락 ≠ 에이전트 메모리.** 메모리는 에이전트가 머리로 기억하는 것, 옵시디언은 사람이 독후감 써서 책꽂이에 꽂는 **도서관**.

## 사서 인사이트 (초안)

1. **이 영상은 우리 집 설계의 타당성 확인서에 가깝다.** 헌법(AGENTS.md) · 역할 분리 · 위키라는 도서관 — 김효율이 27분 내내 권하는 그림을 집은 이미 살고 있다.
2. **경고 두 개.** ① 헌법이 226줄 — 명령 표만 남기고 풀어쓴 설명은 DESIGN-v2로 넘기는 다이어트를 제안할 만하다 (결정은 편집장). ② 「세 번 압축하면 버린다」는 클로드 코드 얘기지만, 사서 세션도 길어지면 같은 병에 걸린다 — 집의 답은 이미 정해져 있다: **중요한 건 세션이 아니라 위키에 남긴다.**
3. 한글 토큰 불리 + 가운데 30% 기억 — 이 집의 모든 대화가 한글이라는 점에서, 「처음에 박아 두기」(계획 모드)와 「끝에 세 줄 세이브」는 우연이 아니라 구조적 정답이었다.
