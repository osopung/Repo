# 오픈소스 BIM 건축 앱 제작 워크플로우

## 내 한 줄

**복잡한 건축 설계 프로그램을 코딩 할 때도 단계별로 하나하나 구동을 감독하는 원리가 핵심이다.

- [x] 감수

## 1단계. 기준과 목표를 정한다

먼저 다음을 분명히 합니다.

```text
기준 + 레퍼런스 → 목표
```

- 어떤 건축 업무에 사용할 것인가?
- 어떤 기능이 필요한가?
- 참고할 BIM 도구나 화면은 무엇인가?
- 결과물의 품질 기준은 무엇인가?

예:

> IFC 파일을 불러와 3D로 확인하고, 건축 데이터를 함께 조회·수정하는 도구를 만든다.

---

## 2단계. 오픈소스와 IFC 표준을 결합한다

다음 도구를 연결합니다.

- **Blender**: 3D 모델링·시각화
- **Bonsai**: Blender 기반 BIM 작업
- **IfcOpenShell**: IFC 파일 처리
- **IFC**: BIM 데이터 교환 표준
- **AI 에이전트**: 도구를 연결하고 작업을 자동화하는 역할

```text
AI 에이전트
    ↓
Blender + Bonsai + IfcOpenShell
    ↓
IFC 기반 BIM 데이터
```

핵심은 상용 BIM 프로그램 하나에 의존하지 않고, 오픈소스 도구와 공개 표준을 조합하는 것입니다.

---

## 3단계. 바이브 코딩으로 자체 앱을 만든다

사람이 자연어로 필요한 앱을 설명합니다.

예:

> “3D IFC Viewer 웹앱을 만들어 줘. IFC 파일을 불러오고, 3D 모델을 회전·확대·축소하며, 건축 요소와 데이터를 확인할 수 있게 해 줘.”

AI 에이전트는 다음을 수행합니다.

1. 요구사항을 해석한다.
2. 필요한 기능을 나눈다.
3. 코드를 작성한다.
4. 프로그램을 실행한다.
5. 오류를 수정한다.
6. 실행 가능한 웹앱을 만든다.

```text
목표 설명
→ 자연어 지시
→ AI 코드 작성
→ 실행 및 오류 수정
→ 자체 IFC Viewer 완성
```

---

## 4단계. 실제로 구동하고 검증한다

만들어진 `cnvifc 스튜디오`를 실제로 실행합니다.

- 프로젝트 3D 도면 불러오기
- IFC 모델 확인
- 모델 회전·확대·축소
- 건축 요소 선택
- BIM 데이터 조회
- 필요한 데이터 수정
- 실제 건축 업무에 사용할 수 있는지 확인

이 단계의 핵심은 **만들었다는 사실이 아니라 실제로 사용할 수 있는지 확인하는 것**입니다.

```text
앱 실행
→ 3D 도면·데이터 불러오기
→ 직접 조작
→ 기준·레퍼런스와 비교
→ 부족한 부분 수정
```

---

## 5단계. 여러 에이전트를 대시보드에서 관리한다

여러 에이전트가 각자 다른 일을 맡게 되면 중앙 대시보드가 필요합니다.

`CnvAgentWorld` 대시보드에서 다음을 확인합니다.

- 어떤 에이전트가 작업 중인지
- 작업이 어느 단계까지 진행됐는지
- 작업이 완료됐는지
- 오류가 발생했는지
- 결과물이 목표와 기준에 맞는지

워크플로우는 다음과 같습니다.

```text
업무를 작은 작업으로 분할
→ 에이전트별 역할 배정
→ 대시보드에 연결
→ 진행 상태 모니터링
→ 오류·지연 조정
→ 결과 검토
```

사람은 모든 작업을 직접 수행하는 대신, 여러 에이전트를 지휘하고 중요한 판단을 맡습니다.

---

# 전체 흐름

```text
기준·레퍼런스 설정
        ↓
건축 업무 목표 정의
        ↓
Blender·Bonsai·IfcOpenShell·IFC 결합
        ↓
AI에게 자체 IFC Viewer 제작 지시
        ↓
에이전트가 코드 작성·실행·수정
        ↓
cnvifc 스튜디오 실제 구동
        ↓
3D 도면·BIM 데이터 조작 및 검증
        ↓
여러 에이전트를 CnvAgentWorld에서 관리
        ↓
결과를 기준과 비교하고 개선
```

## 핵심 한 줄

> **사람은 기준과 목표를 정하고, AI 에이전트는 오픈소스 도구를 연결해 BIM 앱을 만들며, 사람은 실제 구동 결과와 여러 에이전트의 작업을 감독합니다.**
