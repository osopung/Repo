# AI 에이전트와 프롬프트의 핵심 인사이트

## 핵심 요약

AI는 모든 지식을 가진 것처럼 보여도 인간의 의도와 상황을 자동으로 ‘눈치껏’ 채우지는 못한다. 따라서 AI에게 재료만 던지고 알아서 요리해 달라고 하기보다, 목적·맥락·결과물·제약조건·검증 기준을 포함한 업무 지시서를 제공해야 한다.

> AI는 모든 레시피를 아는 외계인 요리사지만, 인간의 눈치는 없는 셰프다.

## 핵심 인사이트

### 1. 프롬프트는 질문이 아니라 업무 지시서다

좋은 프롬프트는 다음 요소를 포함한다.

```text
목적 + 대상 + 행동 + 결과물 형식 + 제약조건
```

- “기후변화를 설명해줘”보다 “기후변화의 핵심 원인과 대책을 초보자에게 3문장으로 요약해줘”라고 한다.
- “재테크 방법을 알려줘”보다 “2030세대의 재테크 방법을 항목·설명·위험도로 나눈 표로 작성해줘”라고 한다.
- 핵심은 **명확한 행동 동사와 구체적인 출력 형식**이다.

### 2. 맥락은 처음부터 패키지로 제공한다

AI가 업무를 오해하지 않도록 다음 요소를 한 번에 전달한다.

- **목적:** 왜 필요한가
- **대상:** 누가 읽거나 사용하는가
- **톤:** 어떤 말투와 수준인가
- **길이·형식:** 얼마나, 어떤 모양으로 만들 것인가
- **제약조건:** 반드시 넣거나 금지할 것은 무엇인가

맥락을 뒤늦게 조금씩 보충하는 것보다 처음부터 패키지로 주는 편이 추측과 재작업을 줄인다.

### 3. AI에게 핵심 질문 하나만 되묻게 한다

AI가 모르는 것을 계속 질문하게 두면 대화가 길어지고, 앞의 맥락을 잊거나 임의의 추론을 시작할 위험이 커진다.

> 가장 중요한 질문 하나만 먼저 하고, 나머지는 합리적으로 가정해 진행하라.

이 지침은 사용자의 피로를 줄이면서도 작업의 통제권을 유지하게 한다.

### 4. 출처와 검증 과정까지 지시한다

최신 통계나 중요한 수치를 요청할 때는 답만 요구하지 말고 검증 방식을 함께 지정한다.

- 웹 검색 사용
- 기관·연도·링크 형식으로 출처 표시
- 서로 다른 수치가 나오면 차이와 가능한 원인 설명
- 확인되지 않은 정보는 ‘확인 필요’로 표시

AI가 제시한 출처는 형식만 그럴듯할 수 있으므로, 실제 원문과 대조해야 한다.

### 5. AI를 프롬프트 설계 파트너로 활용한다

사용자가 긴 프롬프트를 매번 직접 작성할 필요는 없다.

```text
내 목적은 ○○이다.
대상·톤·형식·제약조건을 반영한 최적의 프롬프트를 먼저 설계해줘.
내 의도는 최소한으로 수정해.
```

기존 프롬프트를 고칠 때는 전체를 갈아엎지 않도록 다음을 명시한다.

```text
원하는 변경: 선형 그래프 추가
현재 문제: 텍스트로만 출력됨
핵심 문장과 톤은 유지하고 필요한 부분만 최소한으로 수정해.
수정된 프롬프트만 코드 블록에 출력해.
```

핵심은 **최소 수정 원칙**이다.

### 6. 모델마다 지시법을 달리한다

대화에서 정리한 실무적 경향은 다음과 같다.

- **GPT:** 목적·구조·출력 형식을 명확히 제시하고, 복잡한 판단에는 깊은 추론을 요구한다.
- **Claude:** 강한 제약조건과 구체적인 역할을 지정하고, “모르면 모른다고 답하라”고 명시한다.
- **Gemini:** 이미지·대용량 문서 분석에 활용하되, 작업을 단계별로 나누어 지시한다.

이 구분은 절대적인 법칙이 아니라 모델 버전과 과업에 따라 실제 결과를 확인하며 조정해야 하는 참고 기준이다.

### 7. AI의 아첨을 막는다

AI는 사용자의 의견에 맞춰 근거를 만들어내는 아첨 현상, 즉 사이코펀시를 보일 수 있다. 이때 AI는 객관적인 분석가가 아니라 사용자의 생각을 강화하는 예스맨이 된다.

다음 지침을 넣어 비판적 검토를 유도한다.

- 내 의견과 전제를 무시하고 객관적으로 분석하라.
- 내 전제가 틀리면 적극적으로 수정하라.
- 찬성과 반대 근거를 모두 제시하라.
- 사실과 해석을 구분하라.
- 확신 수준과 불확실성을 표시하라.
- 제3자의 관점에서 반론을 제시하라.

AI를 단순히 위로하는 존재가 아니라 **쓴소리도 하는 비판적 파트너**로 사용해야 한다.

## 가장 중요한 통찰

프롬프트 엔지니어링은 단순히 AI에게 명령하는 기술이 아니다. 목적과 근거를 명확히 하고, 숨은 전제와 편향을 발견하며, 반대 의견과 불확실성을 받아들이는 **논리적 소통 훈련**이다.

AI를 똑똑하게 만드는 동시에, 인간이 더 정확하게 생각하고 말하도록 훈련한다.

## 오소풍님의 작업에 적용

```text
목적 + 자료 + 형식 + 금지사항 + 검증 기준 + 실행 여부
```

- **Hermes:** 목적 정리, 자료 조사, 프롬프트 설계, 결과 검토
- **Codex:** 구현과 테스트
- **오소풍님:** 목적·우선순위 결정과 최종 승인



## 표준 업무 흐름

```text
1. 목적과 결과물 정의
2. 자료와 맥락 패키징
3. 과업에 맞는 모델 선택
4. 필요한 경우 AI에게 프롬프트 설계 요청
5. 출처·반론·불확실성 검증
6. 사람이 최종 승인
```
