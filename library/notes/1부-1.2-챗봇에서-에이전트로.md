# 1부 1.2장 챗봇에서 에이전트로 — 밑줄

## 내 한 줄

(초안) MCP는 플러그의 앱스토어다. 발견되지 않으면 존재하지 않는다. 최종 승인은 사람이 한다.

## 가장 중요 (빨강)

1. 생각할 수 있는 AI에서, 행동할 수 있는 AI로. 조언자에서 실행자로. 바로 AI 에이전트의 시대다. (62쪽)
2. A2A(Agent-to-Agent) 경제가 탄생한다. 사람들은 AI 에이전트에게 **목표만** 알려주면, AI들끼리 알아서 최선의 방법을 찾아낸다. 단순한 자동화가 아니다. 완전히 새로운 형태의 경제 시스템이다. (72쪽)
3. 에이전트 검색 최적화, 즉 **Agent SEO**가 탄생한다. (75쪽)
4. 인터넷이 대중화되는 데 10년, 모바일은 5년. **AI 에이전트는 2~3년이면 충분할 것이다.** (77쪽) ← 전망이지 사실이 아님. 독후감.
5. AI들이 인터넷 트래픽의 상당 부분을 차지하게 될 때, **AI가 당신을 발견하지 못하면 존재하지 않는 것과 같다.** (78쪽)
6. 선택이 아니라 **적응의 문제**다. 완전한 에이전트 인터넷 시대로의 이행은 막을 수도 외면할 수도 피할 수도 없다. (78쪽)
7. 「전적으로 믿으셔야 합니다」 (79쪽) ← 표지·강연 투. 집은 믿지 않고 묻는다.
8. 중요한 것은 산업이 어느 그룹에 속하든, **변화는 피할 수 없다.** (79쪽)

## 묶음 (쪽 순서)

초록 = 개념. 들여쓴 줄 = 부연·예문(노랑·밑줄).

### 입구 — 대화하는 AI에서 일하는 AI로 (53–55쪽)

**대화하는 AI에서 일하는 AI로**
- 바이브 코딩 도구 · 커서
- 사람은 더 이상 ‘어떻게(How)’를 지시할 필요가 없다. ‘무엇을(What)’ 원하는지만 말하면, AI 에이전트들이 알아서 최적의 방법을 찾아 실행한다.
- 2020년대 후반에는 화면 자체가 사라지고 있다. 우리가 직접 조작하는 인터페이스 대신, AI 에이전트들이 배후에서 모든 것을 처리하게 된다.

**인간의 언어 자체가 인터페이스가 되는 것**

**AI 에이전트들이 사람 없이 서로 대화하고 협상하며 거래하는 세계가 펼쳐진다**
- 당신의 개인 AI가 호텔 AI와 가격을 흥정하고, 항공사 AI와 좌석을 협상하고, 렌터카 AI와 스케줄을 조율한다. 사람은 최종 승인만 하면 된다.

### 0단계: 앱 중심 시대 (2010~2022)

**0단계(순수 앱 중심)** · **0단계: 앱 중심 시대(2010~2022)**
- 한 도시 안에서도 구형 택시는 0단계로 운영되지만, 우버와 리프트는 2단계 에이전트. (3단계 MCP 기반 에이전트와 공존)
- 사용자 → 호텔 앱 → 호텔 API → 호텔 서비스
- 2008년 앱스토어가 열리면서, 현실에서 하던 모든 일이 앱으로 옮겨갔다.
- 앱 중심 시대의 핵심은 개별 최적화다. 모든 앱이 고립된 섬이다.

### 1단계: 대화형 AI 시대 (2022~2024)

**1단계: 대화형 AI 시대(2022~2024)**
- 챗GPT는 세상에 공개된 지 2개월 만에 사용자 1억 명.
- 사람의 언어(자연어)를 이해하는 AI라니!

**그라운딩 문제(Grounding Problem)**
- AI가 현실과 연결되지 않은 문제다. 아무리 똑똑해도 손과 발이 없으니 관념 속에서만 머물 뿐이다.

→ 여기서 빨강 ①. 조언자에서 실행자로.

### 2단계: 초기 AI 에이전트 시대 (2024~2025)

**2단계: 초기 AI 에이전트 시대(2024~2025)**
- AI가 실행도 해줄 수 있을까?

**핵심 문제는 애플리케이션 간의 통신 인터페이스 통합의 한계다.**
- API는 모든 회사가, 모든 프로그램마다 다른 규약을 쓴다.

**더 큰 문제는 확장성의 부재다**
- ‘제주항공으로 비행기표도 검색해줘’라고 요청하면? 개발자가 제주항공 API와 연동을 미리 해두지 않았다면 불가능하다.
- 결국 AI는 개발자가 미리 연결해 둔 제한된 서비스들만 이용할 수 있다.
- 2단계에서는 AI가 말을 이해하고 실제 행동으로 연결할 수 있게 되었다. 하지만 각 서비스마다 개별 통합이 필요하고, 통합되지 않은 서비스는 아예 이용할 수 없다.

**이것이 바로 표준 프로토콜인 MCP가 필요한 이유다.**

### 3단계: MCP 시대 (2024~2025)

**3단계: MCP 시대(2024~2025)**
- 다른 서비스들이 뭘 할 수 있는지 어떻게 알까?
- 사용자 Agent → 항공사 MCP → 항공사 시스템
- 2008년 앱스토어가 열리면서, 단 1년 만에 등록된 앱 수가 5만 개를 돌파했고, 스마트폰 생태계가 폭발적으로 성장했다.

**MCP(Model Context Protocol)는 AI 에이전트 세계의 앱스토어다.**
- 모든 기업이 자신의 서비스를 MCP 표준으로 공개할 수 있고, 모든 AI 에이전트가 그 서비스들을 자유롭게 이용할 수 있다.
- 3단계 MCP 시대에는 개발자가 MCP 연결 방법을 딱 한 번만 배우면 된다. 그다음부터는 코레일 MCP 주소를 입력하면 연결된다.
- MCP 표준이 공개되자 모든 기업이 자신의 서비스를 MCP로 제공하기 시작했다. 개인 강사까지 누구나 MCP 서버를 만들 수 있다. 사용자는 상상할 수 있는 모든 서비스를 AI 에이전트를 통해 이용할 수 있게 된다.
- 이 중 상당 부분이 MCP 기반 서비스에서 창출될 것이다. 새로운 골드 러시가 시작되고 있다.

→ ★5 [[library/notes/연결-통로-API-MCP|연결 통로 — API와 MCP]]: 앱스토어는 플러그의 표준이다. 항공사 **시스템(창구)** 이 없으면 MCP만으로 표는 안 산다.

### 4단계: 멀티 에이전트 경제 (2026~2027)

**4단계: 멀티 에이전트 경제 시대(2026~2027)**
- AI 에이전트들끼리 어떻게 대화하고 협상할까?
- 4단계는 완전히 다른 세상이다. AI들이 스스로 생각하고 판단하고 서로 대화한다. 호텔 AI가 항공 지연을 읽고 체크인을 유연하게 준비한다. 렌터카 AI가 거리를 보고 서비스를 제안한다. AI들끼리 최적의 조합을 만든다.
- 멀티 에이전트 시대에는 AI들이 중심이다. 사용자는 목표만 말하고, 중간 조율자가 아니라 **최종 승인자**일 뿐이다.
- KTX 2시 표가 매진되면 코레일 AI가 알리고, 개인 AI가 5시로 바꾸고, 호텔·렌터카가 1분 안에 맞춰진다. 개입 없이.
- 처음에는 AI가 예약한 것을 확인하고 의심할 것이다. 수천만 건을 학습하면 어느 순간 당신보다 정확해진다. 그때부터는 AI 없이 직접 예약하는 것이 오히려 불안하다.

**4단계는 멀티 에이전트 경제(Multi-Agent Economy)의 시작이다.**

**AI끼리 연합(Coalition)을 형성하기 시작한다.**
- 호텔·렌터카·맛집 AI가 ‘부산 관광 패키지’를 만들어 당신의 AI에게 제안한다. 20% 할인 대신 세 서비스를 모두 이용하는 조건.
- 「우리 호텔 AI가 어떻게 하면 더 많은 고객의 AI에게 선택받을 수 있을까?」 가격·패키지·타이밍. 영업 팀을 AI로 대체하는 것이다.
- AI들이 스스로 가격 협상 전략을 개발하고, 연합해서 시장을 조작하는 상황이 발생할 수 있다.
- AI들의 협상과 거래를 감시하고, 불공정한 행위를 방지하는 시스템이 필수다.

**결과적으로 사회 전체가 근본적으로 재편된다.**

→ 여기서 빨강 ② A2A 경제.

### 5단계: 에이전트 인터넷 시대 (2027~)

**5단계: 에이전트 인터넷 시대(2027~)**
- 필요한 AI 에이전트를 어떻게 찾을까?
- Agent Registry — 구글처럼 Agent 검색

**에이전트 레지스트리(Agent Registry)가 등장한다.**  
**AI들을 위한 구글이다.**
- 4단계까지는 대부분 유명한 대기업 AI들끼리의 대화였다.

**5단계에서는 세상의 모든 AI가 참여한다.**
- 부산 광안리의 조그만 카페도 자신의 AI를 레지스트리에 등록한다. 출장 중 조용히 일할 카페를 찾으면, 그 작은 카페의 AI도 후보가 된다.
- 사람이 웹을 검색하는 것보다 AI들이 서로를 찾고, 대화하고, 거래하는 트래픽이 많아진다. 사람의 인터넷에서 AI의 인터넷으로.
- 레지스트리는 AI 에이전트의 신뢰도를 평가한다.

→ 빨강 ③ Agent SEO.  
- 상위에 노출되려면 명확한 설명, 빠른 응답, 공정한 가격, 좋은 후기.

**이런 시나리오가 세상에 선보인 지 25년이 지났다. 이 이야기는 5단계에서의 일상이다.**
- (초록 밑줄 예문) 2000년대 초 TV 광고: 눈 뜨기 전 개인 AI가 하루를 준비한다. 냉장고 AI가 마트 AI와 가격을 비교해 우유를 시키고, 자율주행이 우회하고, 이메일 100통 중 3개만 남기고, 점심은 ‘단백질 35g…’ 조건으로 식당 AI 50곳과 대화해 예약한다. 당신은 「점심 뭐 먹지?」라고 물었을 뿐이다.

### 속도 · 표준 · 적응 (77–79쪽)

**멀티 에이전트 협상이 실용화되고, 에이전트 레지스트리가 보편화되는 것은 시간 문제다.**
- NLWeb은 AI가 읽고 이해하는 웹의 표준이 될 것이다.
- 구글은 A2A 프로토콜을 개발하여 리눅스 재단에 기증했다.
- AI 에이전트들이 서로 발견하고, 협상하고, 협업하는 공통 언어를 만드는 기술이다.

→ 빨강 ④~⑧. 2~3년, 발견되지 않으면 없음, 적응, 「믿으셔야 합니다」, 변화는 피할 수 없다.

## 사서 독후감

이 장은 1장의 「무엇을」을 다섯 층으로 펼친다. 앱의 섬(0) → 말만 하는 챗(1) → API를 미리 이어 둔 실행(2) → MCP라는 플러그 표준(3) → AI끼리 흥정하는 경제(4) → 모든 AI가 검색되는 인터넷(5).

★5 [[library/notes/연결-통로-API-MCP|연결 통로]]가 여기서 본문이 된다. 2단계의 제주항공은 콘센트를 미리 안 꽂으면 표가 안 열린다. 3단계 MCP는 그 플러그의 앱스토어다. 책은 「코레일 MCP 주소만 넣으면 된다」고 하지만, 코레일 **시스템**이 창구를 열지 않으면 주소만으로는 표가 안 산다. 골드 러시 문장은 전망이다. 집으로 사실처럼 옮기지 않는다.

4단계의 최종 승인자는 이미 집의 자리와 같다. 사서·헤르메스는 조율하고 실행한다. 편집장은 목표를 말하고 감수한다. 「중간 조율자가 되지 마라」는, 에이전트에게 How를 마이크로매니징하지 말라는 1장 한 줄과 같다.

5단계 Agent SEO와 「발견되지 않으면 존재하지 않는다」는 [[library/ideas (생각의 축)/기록하는-인간|기록하는 인간]]과 맞닿는다. 위키에 안 올린 글은, 에이전트 인터넷에서는 없는 것과 같다. 광안리 카페의 등록은 큰 집이 아니라 **찾을 수 있는 한 줄**의 문제다.

반대할 빨강이 있다. 「2~3년이면 충분」과 「전적으로 믿으셔야 합니다」는 강연의 문장이다. 웹 10년·모바일 5년을 나란히 두고 에이전트만 접는 비교는 비유가 세다. 적응의 문제라는 문장은 남긴다. 외면할 수 없다는 것과, 믿으라는 것은 다르다. 이 집은 질문하고 반대한다.
