# Hermes 영상에서 배울 인사이트

## 내 한 줄

**목적을 먼저 정하고, 자료와 역할을 나누고, 작은 단계로 실행한 뒤 결과를 확인하면서 AI를 길들인다.**

- [x] 감수

## 핵심

Hermes는 단순히 질문에 답하는 AI가 아니라, 파일 작성·수정, GitHub 작업, 반복 절차 실행, 기억 활용, 전문 도구 연결까지 수행하는 개인 작업 환경이다.

> AI를 잘 쓰는 핵심은 질문을 잘하는 것만이 아니라, AI가 실제로 일을 끝낼 수 있는 환경과 절차를 만드는 데 있다.

## 1. 메모리와 기록을 구분한다

- 오래 유지할 사용자 취향·원칙 → 메모리
- 한 번 끝난 작업·임시 계획 → 세션 기록
- 선별해 보존할 글 → 위키 inbox
- 원본 자료 → Zotero 등 원본 보관처

> 기억을 많이 저장하는 것보다, 무엇을 장기 기억으로 남길지 선별하는 것이 중요하다.

## 2. 스킬은 AI의 작업 매뉴얼이다

스킬은 특정 작업을 안정적으로 처리하기 위한 재사용 가능한 절차다.

- GitHub 파일 작성·push 절차
- YouTube 자료 정리 절차
- 문서 작성 규칙
- ETF 프로그램 단계별 개발 규칙

좋은 작업 절차를 스킬로 만들어 두면 같은 설명을 반복하지 않아도 된다.

## 3. 업무에 맞는 모델을 배치한다

모든 일을 하나의 모델에 맡길 필요는 없다.

- 짧은 판단·실행 → 빠른 모델
- 긴 녹취·에세이 → 긴 문맥에 강한 모델
- 사진·영상 분석 → 멀티모달 모델
- 코딩·오류 수정 → 코딩에 강한 모델

중요한 것은 가장 좋은 모델 하나가 아니라 업무에 맞는 모델을 배치하는 것이다.

## 4. AI의 역할을 나눈다

- 오소풍님 → 목적·기준·최종 판단
- Hermes → 일상 지원·자료 정리·실행
- Codex → 코드 구현·테스트
- Cursor 사서 → 위키 구조·정식 반영·감수
- Zotero → 원본 자료 보관

역할을 나누면 하나의 AI에게 모든 일을 맡기는 것보다 결과가 안정적이다.

## 5. 구현은 설계와 검증을 나누어 진행한다

```text
설계
→ 승인
→ 작은 단계 구현
→ 테스트
→ 결과 보고
→ 다음 단계 승인
```

월배당 ETF 대시보드도 이 순서로 만들었기 때문에 복잡한 투자관리 시스템이 아니라, 10개 이하 ETF의 현황을 한눈에 보는 도구로 정리할 수 있었다.

## 6. 사용자의 원칙이 결과를 결정한다

월배당 ETF 대시보드를 만들 때 다음 원칙을 적용했다.

- 계좌·거래 원장은 제외
- 10개 이하 ETF로 제한
- 한눈에 현황 파악
- 국내·해외 ETF 가격을 모두 원화로 통일
- 환율 기능 제거
- 공식 배당 발표를 우선 사용
- 불확실한 값은 표시 상태를 구분

다만 최종 대시보드에서는 **공식 배당 발표만 사용한 것이 아니다.** 공식 데이터가 없는 기간에는 과거 데이터를 기준으로 한 추정치를 함께 사용해 대시보드의 빈칸을 줄였다.

이 추정치는 공식 수치가 아니라 다음처럼 표시해야 한다.

> **과거 기준 추정값**

즉, 배당금 표시는 다음 세 가지를 구분한다.

- 공식 발표 기준 세전 예상액
- 과거 기준 추정값
- 확인 필요

> AI는 기능을 계속 추가하는 데 강하지만, 무엇을 빼고 어떤 정보를 참고용으로 보여 줄지는 사용자가 결정해야 한다.

## 오소풍님이 배울 한 가지

Hermes를 잘 쓰는 핵심은 많은 기능을 배우는 것이 아니라 다음 구조를 만드는 것이다.

```text
내 목적
→ 내 원칙
→ 자료의 위치
→ AI의 역할
→ 실행 절차
→ 검증 방법
```

이를 한 줄로 줄이면 다음과 같다.

> **목적을 먼저 정하고, 자료와 역할을 나누고, 작은 단계로 실행한 뒤, 결과를 확인하면서 AI를 길들인다.**
