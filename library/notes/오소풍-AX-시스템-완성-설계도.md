# 오소풍 AX 시스템 — 완성 설계도 ★5

> 확정: 2026-09-05 — 8원칙 진단 → 수선 4개 승인 → 완성

## 내 한 줄

(초안) 사람과 여섯 에이전트가 하나의 집(GitHub `osopung/Repo`)을 읽고, 쓰기는 inbox 문 하나로만 들어오며, 위키가 원천이고 헤르메스 3종은 파생이다 — 이것이 오소풍 AX 시스템의 완성된 뼈대다.

## 왜 고쳤는가

에이전트가 여섯(사서·고문·클라우드 커스·헤르메스·코덱스·챗지피티)으로 늘면서 집에 드나드는 문과 규칙이 제각각이었다 — 코덱스는 문밖(집 Git 금지), 고문·헤르메스는 inbox, 지침은 쏟아붓기 통로에 상주, 스킬·Cron은 흩어져 있었다. 8원칙 진단에서 ④(스킬)⑤(하네스)⑥(루프)가 무너져 있음이 드러났다.

**목적은 하나** — 사람과 에이전트가 **같은 집을 읽고**, 쓰기는 **inbox 문 하나**로 모은다. 그래야 집이 한 권의 책처럼 읽히고, 어떤 에이전트와 일해도 맥락이 이어진다. 이것이 개인용 AX 시스템의 뼈대다.

그래서 2026-09-05에 다섯을 고쳤다: ① 쓰기 문을 inbox 하나로 통일 (코덱스 개통) ② 지침 3종 → `library/ops/` ③ 활성 스킬 → `library/skills/` + 레지스트리 [[map/moc/스킬]] ④ 위키=원천 · 헤르메스 3종=파생 선언 ⑤ weekly에 스킬 개선 후보 1개 (상행 루프).

## 여섯 에이전트 레인

| | 자리 | 하는 일 | 읽기 | 쓰기 |
|---|------|---------|------|------|
| **사서** (맥 Cursor) | 맥 | ingest · daily · 감수 정식화 · lint · 대화록 | 집 전체 | 집 전체 (규칙 안) |
| **고문** (윈도우 로컬 Cursor) | 윈도우 | 조언 · 대조 · 자문 | 집 전체 | `inbox/`만 |
| **클라우드 커스** (Cursor Cloud) | 클라우드 | 공장 본업 · ingest 초안 | 집 전체 | `inbox/`만 |
| **헤르메스** (VPS) | 아이폰·텔레그램 | 24시간 비서 · 자료검색 Cron · 재료 수집 | 집 전체 (clone) | `inbox/`만 |
| **코덱스** (윈도우 ChatGPT · Codex) | 윈도우 | 공장(Factory) 프로그램·앱 | 집 전체 | `inbox/`만 |
| **챗지피티** (Work Agent) | 윈도우 ChatGPT | 문서·조사·정리 작업 | 집 전체 | `inbox/`만 (전용 로컬 클론) |

공통 규칙 (inbox 레인): 쓰기 전 `git pull --ff-only` → `inbox/*.md`만 → commit·push → 사서에게 알림. 집 본문 직접 수정 금지.

## 문지방 (지킬 자리)

- **쓰기는 inbox 하나** — 사서 외 누구도 집 본문을 직접 고치지 않는다.
- **위키 = 원천, 헤르메스 3종(SOUL·MEMORY·USER) = 파생** — 바꿀 때 위키(AGENTS·`library/ops/` 지침)부터 고치고 3종에 반영한다. (2026-09-05 선언)
- **공장([`osopung/Factory`](https://github.com/osopung/Factory))과 집은 다른 집** — 코덱스는 양쪽에 발을 걸치되 레인을 지킨다. API 키·비밀번호·OAuth 실값은 어느 레포에도 넣지 않는다.
- 결제·삭제·외부 공개는 편집장 확인 없이 하지 않는다.

## 굴러가는 모습

**하루**

1. **07:00** 헤르메스가 자료 10개를 텔레그램으로 (Cron · job `d7875f02ac92`)
2. 편집장이 아이폰으로 링크·메모를 inbox에 툭툭
3. 맥에서 사서 접속 → pull → ingest → daily → 캘린더
4. 윈도우에서 고문과 긴 대조·자문 → 집에 남길 글만 inbox push
5. 코덱스가 공장에서 만들다가 집용 산출물이 생기면 inbox push
6. 사서가 pull → ingest → 감수 요청 → 편집장이 `[x]`
7. 고친 날은 사서가 commit·push — 시차가 하루를 넘지 않는다

**주일 아침** — 지난주 weekly (편집장이 말하지 않아도) + **스킬 개선 후보 1개** (상행 루프)

## 사서 인사이트 (초안)

이 설계의 힘은 「문이 하나」라는 데 있다. 에이전트가 넷으로 늘어도 쓰기의 문이 inbox 하나라면, 집은 언제나 한 권의 책처럼 읽힌다. 반대로 문이 넷이면 집은 네 조각이 된다. 8/15에 코덱스의 문을 닫았던 것도, 9/5에 다시 연 것도 같은 원칙 — **문의 수가 아니라 문의 모양을 통일하는 것**이 통합이다.
