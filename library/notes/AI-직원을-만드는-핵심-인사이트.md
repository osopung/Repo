# AI 직원을 만드는 핵심 인사이트

## 내 한 줄

 AI 직원을 만드는 일은 정체성·기억·규칙·매뉴얼·일정·보고 체계를 갖춘 업무 시스템을 설계하는 일이다.

- [x] 감수

## 1. 질문에 답하는 도구에서, 정해진 일을 하는 직원으로

매번 이메일 정리·일정 확인을 요청하는 대신, 다음을 미리 둔다.

==```text
직원 정체성
→ 기억
→ 업무 규칙
→ 업무 매뉴얼
→ 실행 일정
→ 보고 채널
```

정해진 시간에 일을 하고 결과를 보고하는 구조가 된다.

> **AI 직원은 좋은 프롬프트 하나가 아니라, 반복 업무를 맡길 수 있는 운영 체계다.**

## 2. 세팅의 다섯 가지

### ① `SOUL.md` — 직원의 정체성

이름·역할·담당·미션·말투·기준·하지 말 것·보고 방식. 신분증이자 직무기술서. 처음부터 완벽히 쓰지 말고, 초안을 두고 쓰면서 고친다.

### ② `USER.md` · `MEMORY.md` — 사용자와의 기억

호칭·답변 형식·장기 취향·업무 원칙. 모든 것을 넣으면 안 된다.

> **오래 유지될 중요한 정보만 남기고, 일회성 작업과 임시 계획은 저장하지 않는다.**

새 기억을 바로 쓰려면 세션을 다시 열어야 할 수 있다.

### ③ `AGENTS.md` — 공통 업무 규칙

보안·작업 경로·저장 위치·소통·보고 양식·판단이 필요한 상황. `SOUL.md`가 「어떤 직원인가」, `AGENTS.md`가 「어떻게 일해야 하는가」.

### ④ Skills — 구체적인 업무 매뉴얼

모닝 브리프, 이메일 요약, 시장 조사처럼 **한 일의 순서**. 공통 규칙은 `AGENTS.md`에 두고, 반복 업무의 자세한 순서는 스킬로 나눈다.

### ⑤ Cron과 보고 채널 — 출근 시간과 보고 장소

언제 무엇을 할지, 결과를 Telegram·Slack·메일·로컬 파일 어디로 보낼지.

> **업무 일정과 보고 채널이 연결되어야 AI가 실제 직원처럼 작동한다.**

## 3. 기억과 매뉴얼을 한곳에 넣지 않는다

| 문서 | 역할 |
|---|---|
| `SOUL.md` | 정체성·태도·미션 |
| `USER.md` | 사용자 기본 정보와 선호 |
| `MEMORY.md` | 장기적으로 기억할 사실 |
| `AGENTS.md` | 공통 업무 규칙 |
| Skills | 특정 업무의 상세 매뉴얼 |
| Cron | 실행 시간과 반복 일정 |

> **정체성, 기억, 규칙, 매뉴얼, 일정은 서로 다른 층위다.**

## 4. 짧게 시작하고 쓰면서 발전시킨다

1. `SOUL.md`와 기본 기억
2. 간단한 일 하나
3. 결과 확인
4. 부족한 점을 규칙·스킬에 추가
5. 안정되면 Cron
6. 조금씩 확장

> **AI 직원은 한 번에 완성하는 것이 아니라, 실제 업무를 시키며 온보딩한다.**

## 5. 메모리는 정기적으로 검진한다

용량 제한이 있다. 불필요·낡은 선호·중복·긴 문장·핵심 원칙을 표로 제안하게 한 뒤, **사람이 선택**한다.

## 6. 큰 일은 계획, 작은 일은 바로

```text
목표 확인 → 자료 확인 → 순서 작성 → 계획 승인 → 실행 → 결과 보고
```

> **작은 일은 자동 실행하고, 큰 일은 계획과 승인을 거친다.**

## 7. 자동화에는 안전장치

항상 보고할지, 조건이 있을 때만 알릴지, 파일만 둘지. 메일 전송·외부 공개·삭제·결제는 승인 절차.

## 8. 많아지면 프로필로 나눈다

콘텐츠·리서치·일정처럼 역할별 프로필. 처음부터 여러 명을 만들기보다, **한 명을 먼저 제대로**.

## 오소풍에게

헤르메스 운영은 이미 이 방향과 맞다. 그림자 비서 · 장기 기억 · 스킬 · 위키 inbox · Telegram · Cron.

앞으로 필요한 것은 기능을 많이 넣는 것이 아니라:

==1. 업무별 매뉴얼을 스킬로 분리하고
==1. ==반복 업무만 Cron으로 자동화하고
1. 보고가 필요한 일과 조용히 처리할 일을 구분하는 것이다.
