# 코덱스 활용의 핵심 인사이트

## 내 한 줄

코덱스를 잘 쓰는 사람은 프로젝트 폴더·맥락 문서·검증 절차·Git 기록을 갖추고 아이디어를 실제 결과물까지 연결하는 사람이다.

- [x] 감수

## 1. 답변 도구가 아니라 작업 동료

파일을 만들고 고치고, 코드를 실행하고, 브라우저에서 확인하고, GitHub·Gmail·Vercel과 연결한다.

> **코덱스는 아이디어를 문서·코드·이미지·웹사이트로 바꾸는 실행형 동료다.**

집 Git·inbox에는 손대지 않는다. 공장은 [`osopung/Factory`](https://github.com/osopung/Factory). [[library/notes/코덱스-역할]]

## 2. 아이디어를 채팅으로 끝내지 않는다

==```text
아이디어 → 프로젝트 폴더 → 문서화 → 조사와 기획 → 결과물 제작
```

프로젝트는 코덱스 안의 공간이 아니라, **내 컴퓨터에 실제 파일이 있는 작업 폴더**다.

## 3. `AGENTS.md`는 프로젝트 설명서

목적·방향·기준·문체·규칙. 새 스레드마다 다시 설명하지 않게 한다. 짧게 시작하고, 방향이 바뀌면 고친다.

> **`AGENTS.md`는 AI가 프로젝트의 맥락을 잊지 않도록 하는 기본 안내서다.**

## 4. 문서가 다음 작업의 재료가 된다

시장 조사 → 브랜드 → 비주얼 → 이미지 → 랜딩 → 이메일. 프로젝트 안 문서는 보관용이 아니라 **맥락 데이터베이스**다.

## 5. 작은 작업을 하나의 결과물로 연결한다

구상 → 조사 → 전략 → 이미지 → 메일 → 웹 → 로컬 실행 → 브라우저 검토 → 배포. 앞 단계의 결과를 다음 입력으로 쓴다.

## 6. 커지면 먼저 계획

```text
폴더와 자료 확인 → 순서 계획 → 검토 → 승인 → 구현
```

> **큰 작업은 바로 실행하지 말고 계획부터 확인한다.**

## 7. 브라우저에서 실제 결과를 검증한다

개발 서버 → 페이지 열기 → 버튼·폼 → 모바일 → 화면에 주석을 달아 수정. 코드가 맞는지보다 **실제 사용 화면이 작동하는지**.

## 8. 이미지와 웹페이지도 반복해서 고친다

초안 → 부족한 점 → 바꿀 것/유지할 것 → 수정 → 다시 확인. 지시에는 바꿀 것·유지할 것·배경·추가하지 말 것·로고·워터마크를 가른다.

## 9. GitHub는 안전장치

AI가 여러 파일을 한꺼번에 고친다. 작은 작업 완료 → 커밋 → 중요한 시점에 푸시. 복구·협업·이력.

> **GitHub는 단순 저장소가 아니라 AI와 함께 일하기 위한 복구·협업·이력 관리 장치다.**

공장 Git만. 집 `osopung/Repo`는 코덱스가 열지 않는다.

## 10. 권한은 필요한 만큼만

범위가 명확할 때만 높은 권한. 외부 연결·삭제·배포는 내용을 확인. 모를 때는 기본 승인.

> **편리함이 커질수록 실행 범위와 권한을 확인해야 한다.**

## 11. 외부 도구를 연결하면 흐름이 확장된다

파일 + 웹 자료 + 외부 도구 = 하나의 작업 흐름. 메일 전송·외부 공개는 **최종 확인 후**.

## 12. 공부도 시킬 수 있다

AGENTS.md 설명, Git 커밋과 푸시, 계획 모드, 이 프로젝트에 Next.js를 쓰는 이유. 작업자이면서 맞춤 교사.

## 오소풍에게 — ETF 대시보드에서 쓴 방식

```text
목적 설정 → 설계 → 승인 → 작은 단계 구현 → 테스트 → 화면 확인 → 수정 → 커밋·푸시
```

앞으로 세 가지:

1. 프로젝트 초기에 `AGENTS.md`를 만든다.
2. 큰 작업은 계획 모드에서 먼저 확인한다.
3. 문서·이미지·코드·화면을 **하나의 프로젝트 폴더** 안에서 연결한다. 그 폴더는 공장.
