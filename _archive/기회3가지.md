최근 자료를 보면, 핵심 흐름은 “AI를 실제 작업 완료까지 연결하는 개인 작업 시스템” 구축입니다.

- 성과: Hermes 대시보드 운영 성공, Git 기반 `inbox → 검수·보관` 흐름 정착, Windows 작업 환경의 동기화 문제도 해결된 기록이 있습니다. [Hermes 운영 기록](https://docs.google.com/document/d/1vRhrqEBvgaOek_rtjBle42ZCoSeyqIEb06qkPNUCJnk)
- 계획: AI는 설계·감수하고 Codex가 구현하는 방식으로, 사진·기록·위키 자동화와 월배당 ETF 관리 대시보드를 단계적으로 만들려는 방향입니다. [주간 메모](https://docs.google.com/document/d/18NVjghmjXOwha9jybSm_CyLJ6btd56s9up-vtttV710) · [ETF MVP 계획](https://docs.google.com/document/d/17zpObBZw7v40kkhzUQo-H9SUchsRk52pVZqUgTrMeE0)
- 운영 원칙: 작은 기능 단위, 테스트·승인 우선, 원본 보호, Git 버전 관리가 분명합니다. [바이브코딩 원칙](https://docs.google.com/document/d/17EfiSO5zAoKzuFCaubAv07gBrcZKRVt9v-sV9v7aM3M)

가장 큰 기회는 세 가지입니다.

1. **작업 흐름을 하나의 대시보드로 묶기**  
    Hermes, Git inbox, Codex 작업, 주간 회고를 “진행 중 / 검수 대기 / 완료”로 모으면 현재의 좋은 분업 구조가 눈에 보이는 성과 관리 체계가 됩니다.
    
2. **ETF 대시보드를 첫 번째 완결형 MVP로 삼기**  
    범위가 명확하고 자동매매를 제외해 위험도 낮습니다. CSV 입력 → 보유·배당 계산 → 월간 보고서 순으로 완성하면, 이후 사진·기록 자동화의 재사용 가능한 제작 방식이 됩니다.
    
3. **지식 저장소를 실행 가능한 운영 매뉴얼로 발전시키기**  
    지금은 기록이 여러 문서에 흩어져 있습니다. “목표·현재 상태·다음 행동·완료 기준” 네 항목을 매 프로젝트마다 고정하면 AI와 사람 모두 훨씬 덜 헤맵니다.
    


현재 자료에는 매출·사용자 수·완료율 같은 정량 KPI가 거의 없어, “사업 성과”를 수치로 판단하기는 어렵습니다. 다음 주부터는 프로젝트별로 `이번 주 완료물 1개 / 다음 주 우선순위 1개 / 측정 지표 1개`만 남겨도 성과 검토가 훨씬 선명해집니다.
